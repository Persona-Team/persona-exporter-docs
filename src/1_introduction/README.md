# Введение
## Архитектура потока данных

Процесс и логику работы **Persona Exporter** *(или же любого другого экспортера метрик)*
можно описать следующими схемами:

```mermaid
graph TD
    OS[Операционная система с которой хотите собирать метрики] 
    -->|Сбор метрик: CPU, RAM, Сеть, Датчики, Диски, Процессы| PE(Persona Exporter)
    PE 
    -->|POST-запрос: JSON / Line Protocol| TSDB[(Бекенд)]
```

Или же более подробно. Схема хоть и описывает сбор **Linux** системах, но передает сам механизм сбора
который не зависит от платформы:

```mermaid
flowchart TD
    n6["Запуск экспортера"] --> exporter
    
    subgraph server ["Сервер"]
        exporter["Экспортер"]
        
        subgraph os ["Операционная система"]
            procfs["/proc (папка)"] --> runtime["Счетчики процессов и рантайма"]
            sysfs["/sys (папка)"] --> hardware["Счетчики CPU, памяти и устройств"]
        end

        agent["Агент (Agent)"]
        
        %% Компактные двунаправленные прямые связи
        exporter <-->|читает / возвращает метрики процессов| procfs
        exporter <-->|читает / возвращает системные метрики| sysfs
        
        exporter -->|предоставляет эндпоинт метрик| agent
    end

    metrics[("Хранилище метрик (Backend)")]
    
    agent -->|отправляет метрики на указанный эндпоинт| metrics
```
